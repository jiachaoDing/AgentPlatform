# 开发计划

产品范围与 P0 编号见 [产品定义](product.md)，架构与技术方案状态见 [架构文档](architecture.md)。

## 当前进度与下一步

截至 2026-11-20，M1 的可控环境技术验收已通过：平台身份与用户隔离、受控网络、MCP/A2A、远端 OAuth、队列重启恢复和真实模型混合冒烟测试均有证据。

下一步进入 M2 Hub 核心：建设可审核的服务与客户端登记，绑定个人/团队权限，接入真实登录会话、OAuth 路由和用户连接页面。完成后进入直接测试与持久化执行，再推进 Playground 和 Market。公网服务与授权环境仍需独立验收。

## 里程碑与验收

M1 可控环境技术验收通过，M2–M6 待实现。每项完成后记录实际检查命令、结果与脱敏证据位置，再更新交付状态。

| 阶段 | 交付目标 | 验收范围 |
|---|---|---|
| M1 骨架与技术验证 | 建立前端、API 与共享契约，锁定运行时和依赖。准备独立文本 MCP、文本 A2A、可控 OAuth 服务与模型替身 | 官方 SDK、身份/数据层集成、受控网络传输、远端服务 OAuth、调度恢复可重复验证，确定协议版本。真实模型配置到位后验证工具调用与多轮回传 |
| M2 Hub 核心 | 邀请登录、个人/团队归属、个人能力、元数据与控制权验证、OAuth 连接生命周期 | P0-01/02 的服务添加、P0-10、P0-09 的身份授权边界。两个用户独立授权，个人与团队管理权限、受保护元数据及断开连接均可验证 |
| M3 直接测试 | MCP 参数测试、A2A 文本提交与记录 | P0-06/11、P0-09 的执行安全。Hub 使用用户授权完成远端调用，直接测试模型调用数为零，确认、即时撤权与任务归属正确 |
| M4 Playground | 模型配置、能力选择、工具循环、执行展示及必要历史 | P0-04/05/07/08。真实模型先调用 MCP 再委托 A2A，结果与最终回答可追溯，等待或需要输入的任务如实展示 |
| M5 Market | 发布审核、版本更新、上下架、搜索筛选、分享与安装，贯通统一导航 | P0-01/02 的发布、P0-03、P0-09 的审核。市场安装至 Hub 后独立授权并完成直接测试与混合调用，模块启停不破坏独立路径 |
| M6 公网试点 | 部署、迁移、管理员初始化、备份恢复与运行配置 | 全部 P0 及产品验收场景。真实模型、独立 MCP/A2A、至少两个发布者和两个使用者参与，保存调用关联、状态、模型零调用与负向证据 |

M1 先验证 SDK 能否满足网络与授权边界，再进入服务接入实现。候选依赖以验证结果确定，关键技术决策更新到架构文档，确切版本由依赖配置和锁文件维护。

M1 骨架验证已通过，采用 pg-boss 与 Drizzle 事务共同提交任务，并验证回滚及队列实例重启后的取回。生产执行消费者仍须实现读取权威状态、重新授权与结果核查。Playground 页面在模型与 Hub 正式执行接线完成前禁用发送，组件验证页仅在开发模式提供示例输入。

## 本轮验收证据

以下检查于 2026-11-20 在 Windows、Node.js 24.11.1、pnpm 10.33.0 与 Docker 环境执行。

| 检查 | 结果与证据 |
|---|---|
| `pnpm typecheck`、`pnpm format:check`、`pnpm install --frozen-lockfile` | 应用、共享包及测试类型检查、格式与锁文件安装通过 |
| `pnpm test` | 22 项通过。MCP 实连发现和调用（含无效参数）；A2A 1.0 JSON-RPC 实连发现、立即回复、原任务查询、需要输入及失败；出口验证包含禁止私网/保留地址、混合 DNS 结果、重定向、Card 执行目标、解码后体积和取消/超时；保留模型替身和流式逻辑回归 |
| `pnpm test:integration` | 14 项通过。新增 7 项 OAuth 集成：独立 HTTP 授权夹具与真实 PostgreSQL 验证迁移、MCP/A2A 带令牌调用、用户/会话隔离、回调防重放、issuer/资源/scope、凭证密文、刷新轮换、并发断开及重新授权。平台身份、来源校验与队列回归通过 |
| `pnpm test:e2e --workers=1`（上轮） | 4 项通过。此环境通过 `NO_PROXY` 排除回环地址；默认并行首次运行在页面导航处超时 |
| `pnpm build` | 前后端生产构建通过；对话组件产物仍有体积提示 |
| 真实模型冒烟测试 | `gpt-5.6-sol`，3 次模型请求，先通过独立 HTTP MCP 服务执行工具，再将结果发送给独立 HTTP A2A Agent 并核对最终回答。服务限本地回环；使用合成输入与测试执行网关。复跑方式见 [README](../README.md#真实模型冒烟测试) |

已验证 OAuth 的服务端连接层；站点接线、执行确认、执行记录恢复和公网服务试点属于后续阶段。

M6 同时验证部署、进程重启与调度恢复。首批试点通过校园场景收集指标基线、故障及用户反馈，全部 P0 通过后完成首版验收。

## 必须保留的验收证据

通用实现测试由开发阶段补齐，下表覆盖容易破坏产品或架构边界的回归风险。

| 范围 | 必须证明的行为 |
|---|---|
| 协议与模型 | MCP 工具发现/参数/调用，A2A 消息、异步任务、需要输入与失败，直接模式模型零调用，替身验证多轮逻辑，真实模型验证 MCP → A2A |
| 模块边界 | Market 安装与 Playground 执行使用 Hub 契约，内部仓储归属正确，模块启停不破坏 Hub 独立使用 |
| 能力与版本 | 私人能力所有者隔离、团队管理权限、幂等安装、卸载失效，未审核版本、下架/停用、未启用及参数/版本变化后的执行被正确处理 |
| OAuth 边界 | 远端服务令牌按用户与资源隔离，用户连接隔离、回调防重放、issuer/资源/scope 校验，无刷新令牌、并发轮换、断开与刷新竞态、重新授权及后台查询停止 |
| 出口与凭证 | IPv4/IPv6 与特殊地址、DNS 变化、重定向、Card 执行地址均受控，跨源无凭证泄漏，令牌和客户端密钥加密保存，浏览器、模型及日志脱敏 |
| 确认与恢复 | 批准/拒绝/过期、并发确认、重复提交、入队失败与重复消费、进程重启、超时未知及原任务续查保持一致，未知结果不盲目重提 |
| 用户入口与数据 | 发布、审核、安装、OAuth、直接测试、AI 混合调用与断开端到端贯通，会话及调用内容隔离，删除、备份恢复按已确认规则验收 |
