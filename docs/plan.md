## 里程碑与验收

以下里程碑均待实现。每项完成后记录实际检查命令、结果与脱敏证据位置，再更新交付状态。

| 阶段 | 交付目标 | 验收范围 |
|---|---|---|
| M1 骨架与技术验证 | 建立前端、API、独立 Gateway 与共享契约，锁定运行时和依赖。准备独立文本 MCP、文本 A2A、可控 OAuth 服务与模型替身 | 官方 SDK、身份/数据层集成、受控网络传输、双层 OAuth、调度恢复可重复验证，确定协议版本及外部测试客户端。真实模型配置到位后验证工具调用与多轮回传 |
| M2 Hub 核心 | 邀请登录、个人/团队归属、个人能力、元数据与控制权验证、OAuth 连接生命周期 | P0-01/02 的服务添加、P0-10、P0-09 的身份授权边界。两个用户独立授权，个人与团队管理权限、受保护元数据及断开连接均可验证 |
| M3 直接测试与外部客户端 | MCP 参数测试、A2A 文本提交与记录，Gateway 标准 MCP/A2A 接入 | P0-06/11/12/13、P0-09 的执行安全。真实外部 MCP 客户端和标准 A2A 客户端完成调用，直接测试模型调用数为零，确认、即时撤权与任务归属正确 |
| M4 Playground | 模型配置、能力选择、工具循环、执行展示及必要历史 | P0-04/05/07/08。真实模型先调用 MCP 再委托 A2A，结果与最终回答可追溯，等待或需要输入的任务如实展示 |
| M5 Market | 发布审核、版本更新、上下架、搜索筛选、分享与安装，贯通统一导航 | P0-01/02 的发布、P0-03、P0-09 的审核。市场安装至 Hub 后独立授权并完成直接测试与混合调用，模块启停不破坏独立路径 |
| M6 公网试点 | 部署、迁移、管理员初始化、备份恢复与运行配置 | 全部 P0 及产品验收场景。真实模型、独立 MCP/A2A、外部客户端、至少两个发布者和两个使用者参与，保存调用关联、状态、模型零调用与负向证据 |

M1 先验证 SDK 能否满足网络与授权边界，再进入服务接入实现。候选依赖以验证结果确定，关键技术决策更新到架构文档，确切版本由依赖配置和锁文件维护。

M6 同时验证 API/Gateway 独立部署、进程重启、调度恢复和多实例所需会话路由。首批试点通过校园场景收集指标基线、故障及用户反馈，全部 P0 通过后完成首版验收。

## 必须保留的验收证据

通用实现测试由开发阶段补齐，下表覆盖容易破坏产品或架构边界的回归风险。

| 范围 | 必须证明的行为 |
|---|---|
| 协议与模型 | MCP 工具发现/参数/调用，A2A 消息、异步任务、需要输入与失败，直接模式模型零调用，替身验证多轮逻辑，真实模型验证 MCP → A2A |
| 模块边界 | Market 安装与 Playground 执行使用 Hub 契约，内部仓储归属正确，模块启停及 API/Gateway 独立发布兼容 |
| Gateway | 标准 MCP 与 A2A 客户端可接入，发现与调用使用同一暴露策略，会话、任务与结果按用户、客户端和能力隔离，外部副作用确认及即时撤权生效 |
| 能力与版本 | 私人能力所有者隔离、团队管理权限、幂等安装、卸载失效，未审核版本、下架/停用、未启用及参数/版本变化后的执行被正确处理 |
| OAuth 边界 | 两层令牌分别绑定资源，用户连接隔离、回调防重放、issuer/资源/scope 校验，无刷新令牌、并发轮换、断开与刷新竞态、重新授权及后台查询停止 |
| 出口与凭证 | IPv4/IPv6 与特殊地址、DNS 变化、重定向、Card 执行地址均受控，跨源无凭证泄漏，令牌和客户端密钥加密保存，浏览器、模型及日志脱敏 |
| 确认与恢复 | 批准/拒绝/过期、并发确认、重复提交、入队失败与重复消费、进程重启、超时未知及原任务续查保持一致，未知结果不盲目重提 |
| 用户入口与数据 | 发布、审核、安装、OAuth、直接测试、AI 混合调用与断开端到端贯通，会话及调用内容隔离，删除、备份恢复按已确认规则验收 |
