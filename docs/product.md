# 产品定义

本文件维护已确认的产品范围与用户验收。技术边界见 [架构文档](architecture.md)，交付状态见 [开发计划](plan.md)。

## 为什么做

开发者独立提供的 AI 工具与 Agent 分散在不同服务中，用户难以发现、体验和组合使用，开发者也需要重复处理接口集成。平台通过能力发布、发现、选择、真实调用和使用反馈，降低专业能力的分发与复用门槛。

AI Capability Platform 是面向公众的 AI 能力管理、分发与使用平台，服务个人开发者、开发团队、能力使用者和平台管理员。用户统一管理授权，在平台与外部客户端使用专业能力，开发者通过市场发布和分享能力。

## 做什么

### 统一网站与三个业务模块

统一网站通过顶部导航提供“我的能力”“能力市场”“AI 工作台”三个入口，共享账号、团队和授权体验。

| 模块 | 定位与首版职责 |
|---|---|
| Capability Hub · 我的能力 | 管理个人添加和从市场安装的 MCP/A2A 能力、OAuth 连接、直接测试、调用记录与外部客户端访问授权 |
| Capability Market · 能力市场 | 发现、发布、审核、分享与安装能力，安装时调用 Hub 建立个人能力引用 |
| AI Playground · AI 工作台 | 选择模型，通过自然语言测试和使用 Hub 中已安装、启用且获授权的能力 |

Playground 优先服务能力测试、调试和实际使用，展示参数、授权、调用状态及结果。

### 用户与权限

| 用户 | 核心操作 |
|---|---|
| 能力使用者 | 管理个人能力与 OAuth 连接，直接测试，在 Playground 或获授权外部客户端使用能力，发现和安装市场能力 |
| 发布者，包括个人开发者与开发团队 | 维护有权管理的能力，提交审核、更新、下架，查看获授权的调用信息 |
| 平台管理员 | 管理账号与团队、审核与停用服务、配置模型、排查运行问题 |

服务定义归属于个人发布者或团队，发布权限根据归属和成员关系校验。Hub 中的个人能力引用、用户连接和客户端授权归属于具体用户。用户可同时使用与发布能力，角色按权限分配。

首版采用管理员邀请账号、分配角色和管理团队的准入方式。平台与发布服务部署在公网。经审核上架的能力向所有已登录用户展示，用户通过 OAuth 连接自己的服务账号，平台按该用户授予的权限调用服务。每次执行校验平台账号、服务状态、用户授权和本次启用范围。

### 用户连接与授权

首版 MCP 与 A2A 采用逐用户 OAuth。直接添加或市场安装建立个人能力引用，安装与连接分别管理，用户随后独立连接自己的服务账号。

- 服务详情展示授权目标、所需权限、数据传送与费用信息。连接后展示账号安全摘要、实际授权范围和状态。
- “我的连接”支持重新/补充授权及断开连接。断开立即阻止后续远端请求，清理本地令牌，并在授权方支持时撤销远端授权，已发送任务保留真实状态。
- 用户分别决定 AI 启用范围、允许对外使用的个人能力，以及指定外部客户端可用范围。直接测试、AI 委托和外部调用都使用当前用户的服务授权，副作用操作另按执行确认规则处理。
- 撤销客户端授权、关闭对外使用许可或卸载能力后，对应后续调用失效。远端服务连接在 Hub 中单独管理。

### 第一版交付范围

| 编号 | 交付 | 用户可见验收结果 |
|---|---|---|
| P0-01 | MCP 管理与发布 | Hub 添加远程 Streamable HTTP 服务，读取工具与参数，Market 提供预览与审核上架 |
| P0-02 | A2A 管理与发布 | Hub 添加 Agent，读取 Card 与技能，Market 提供预览与审核上架 |
| P0-03 | 统一市场与安装 | 按关键词、类别、协议、发布者或团队浏览筛选，安装至 Hub，区分信息来源 |
| P0-04 | 模型接入 | 管理员配置模型接口，经过工具调用验证的模型可用于 AI 工作台 |
| P0-05 | AI 调用 MCP | 已选且获授权的工具被真实调用，显示结果与真实错误 |
| P0-06 | 直接 A2A | 无须配置平台模型即可提交文本任务并得到消息或任务状态与结果 |
| P0-07 | 间接 A2A | AI 向已选 Agent 委托文本任务，用户可查看目标、任务内容或安全摘要、状态与结果 |
| P0-08 | 混合调用 | 同一实际对话先调用 MCP，再委托 A2A，最终回答可追溯至真实调用 |
| P0-09 | 基础安全与管理 | 审核、授权、URL 防护、执行确认、超时与失败处理均有验收证据 |
| P0-10 | 用户 OAuth 连接 | 用户分别连接 MCP/A2A，授权记录与令牌按用户隔离，支持刷新、重新授权和断开连接 |
| P0-11 | 工具直接测试 | Hub 输入 MCP 工具参数并真实执行，展示结果与错误，平台模型调用数为零 |
| P0-12 | 外部 MCP 客户端 | 一个真实外部客户端通过独立 Gateway 完成 OAuth 接入，发现并调用获授权 MCP 工具，撤权即时生效 |
| P0-13 | 标准 A2A 网关接口 | 外部 A2A 客户端读取获许可 Agent 信息、提交文本消息/任务并查询状态，权限与结果归属可验证 |

全部 P0 均为首版验收范围。

### P0 所需的最小配套行为

- 支持同时启用 MCP 和 A2A 两项能力，满足混合调用验收。
- 保存必要的会话、调用、确认与远端任务关联信息，支持权限控制和故障排查。
- A2A 返回任务时展示真实状态，支持基本查询或刷新。需要补充输入或其他尚未支持的交互时，显示明确提示和人工交接入口。
- 个人添加的服务仅供所有者使用和测试，公开分享和市场安装使用经过审核的发布版本。
- 管理员核验为只读的工具可直接执行，其余 MCP 操作与 A2A 委托逐次确认。确认展示目标、操作与参数摘要，A2A 直接模式的明确提交可作为该次确认。
- 服务控制权通过同源随机挑战码验证，或由管理员人工核验并保存证据。
- 展示第三方数据传送、访问条件及潜在费用。平台模型用量与远端服务费用分别说明。
- 服务更新后，影响地址、权限、工具或技能的变化需要重新验证及相应审核。

### 后续迭代

- 完整的多能力管理、历史查询与用户数据管理体验。
- A2A 长任务续接、补充输入、取消、文件与丰富产物。
- 对外接入文档、最小 MCP/A2A 示例与部署指引。内部验收先准备可运行文本示例。
- 开发者自助接入、更多认证方式、外部 Agent 的受控访问及使用统计。
- API 能力管理与调用、能力购买及配套交易流程。
- Gateway 的 MCP 与 A2A 跨协议适配。

## 第一版非目标

- 自研大模型、通用 Agent Runtime、Agent Builder 或自动部署发布者应用。
- 复杂 DAG、多 Agent 自动规划、企业流程引擎。
- 统一托管发布者的应用运行环境、模型和数据库。
- 本地 stdio MCP 托管、全版本协议兼容、任意 API 自动转换。
- 无差别兼容所有 A2A 流式、推送、取消与多模态特性。
- 匿名外部 Agent 的无限制调用、自动支付、商业结算、复杂信誉体系。
- 企业级高可用、Kubernetes 调度及本地设备或工作区管理。

## 验收场景

准备发布者 A 的文本处理 MCP 与发布者 B 的报告 A2A，两个服务独立运行。首版以文本传递贯通，PDF 上传与文件转交在后续扩展。

1. A、B 在 Hub 添加服务，平台读取真实元数据，验证连接与直接测试。随后提交 Market 发布，管理员审核。
2. 用户在 Market 搜索并查看两项能力及其来源、状态、访问条件，安装至 Hub。
3. 用户通过 OAuth 连接两项服务，分别直接测试 MCP 工具和报告 Agent，得到真实结果。平台模型调用计数增量为零。
4. 用户在 Playground 启用已连接的两项能力并提交需要文本处理和报告生成的请求。
5. 平台模型先调用 MCP，再把结果交给 A2A，展示完整执行记录和最终回答。
6. 模拟令牌过期、撤销授权、断开连接、服务故障、触发确认或让任务持续运行，界面和记录准确反映实际情况。
7. 第二个用户使用相同能力时独立完成授权，两个用户的账号、令牌、结果与任务查询权限相互隔离。
8. 用户允许指定能力对外使用，授权一个真实外部 MCP 客户端访问 MCP 能力，经 Gateway 发现并调用工具，Hub 显示客户端来源与结果。
9. 外部 A2A 客户端通过 Gateway 的标准 A2A 接口读取 Agent 信息、提交文本任务并查询真实状态，Hub 记录相同的授权与执行关联。
10. 撤销客户端授权、关闭能力对外使用许可、断开远端连接或卸载能力后，外部客户端的后续调用被拒绝。

端到端验收必须包含第 4、5 步。自动化测试可使用可控协议服务与模型替身验证逻辑，正式验收另需真实模型与独立运行服务的证据。

## 试点观察

首批试点邀请学生开发团队、教师和学生参与，通过校园场景验证发布和复用闭环。产品角色、页面文案和业务模型采用发布者、团队、用户等通用概念。

记录有效发布数、成功调用率、跨发布者真实调用数、首次试用耗时、延迟、平台模型用量及发布者维护负担。试点采集基线后确定目标值。
